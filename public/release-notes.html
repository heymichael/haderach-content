Transformation Platform — Release Notes

v1.1 April 5, 2026

New Expense Tracking and Vendor Management domains, better tables in agent chat, contractor access controls, design system documentation, a more consistent experience across domains, and a currency bug fix. The User Guide has been updated to reflect these changes.

New Features

New capabilities added in this release.

Separate Expense Tracking & Vendor Management Domains

What was previously one combined Vendors domain is now two focused domains — Expense Tracking and Vendor Management.

Expense Tracking is where you go to ask questions about spend — totals, breakdowns, trends, and comparisons. Vendor Management is where you look up, edit, and organize your vendor records. Each domain has its own dedicated agent that understands exactly what you need in that context.

Because each agent is focused on fewer tasks, answers are faster and more accurate. You’ll also notice that the Expense Tracking agent no longer volunteers extra information you didn’t ask for. And when you do need to cross over — say, check a vendor’s spend while managing their record — the agents coordinate behind the scenes so you don’t have to switch domains yourself.

Real Tables in Agent Responses

When you ask the agent a data question, the answer now includes a proper table you can read, copy, and download.

Previously, the agent would describe your data in paragraph form — sometimes adding extra numbers you didn’t ask for or formatting things inconsistently. Now, spend breakdowns, rankings, and comparisons appear as clean, structured tables right in the chat. Each table includes a copy button and a CSV download so you can easily move the data into a spreadsheet or share it with your team.

Contractor Access Controls

Finance admins can now mark vendors as contractors and control exactly who can see their invoices, payments, and spend.

When a vendor is flagged as a contractor, their financial details are hidden from all users by default. A finance admin must explicitly grant access to individual team members before they can view that contractor’s spend data. Basic vendor information (name, category, department) remains visible to everyone — only the sensitive financial data is restricted.

New vendors are treated as contractors by default, so nothing is exposed until a finance admin reviews and grants access. There is no automatic carry-over — if an existing vendor is newly marked as a contractor, access is revoked immediately until re-granted.

Components & Design System Documentation

A new section on the docs site lets you browse every UI component, color, font, and brand asset used across the platform.

You can interact with each component directly — toggle options, resize viewports, and see how things look at different screen sizes. The full color palette, typography scale, and spacing system are documented alongside the components. This is available from the “Components & Design System” link on the docs index page.

Improvements

Enhancements to existing functionality.

Consistent Look & Feel Across Domains

Colors, typography, spacing, and component styling are now unified across all domains.

Previously, visual inconsistencies could appear when switching between Vendors, Commodities, and Settings — slightly different button styles, text sizes, or background shades. These domains now share a single design foundation, so the experience feels seamless as you move between them.

Sign-in screens, empty states, chat formatting, and the overall shell all look and behave identically regardless of which domain you’re in.

Bug Fixes

Issues resolved in this release.

Currency Adjustment for Rupee-Denominated Invoices

Fixed an issue where INR-denominated contractor invoices were displaying spend amounts without converting to USD.

Invoices for rupee-denominated contractors were appearing at their original INR values in spend totals and drill-downs, inflating apparent spend. These amounts are now correctly converted to USD before display and aggregation.

This is a temporary fix. A permanent solution will come when the platform switches to QuickBooks as the primary invoice source, which handles multi-currency conversion automatically.
